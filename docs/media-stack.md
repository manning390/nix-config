# Glaciem media stack

The stack is inspired by [notthebee's configuration](https://git.notthebe.ee/notthebee/nix-config/src/branch/main/modules/homelab/services), adapted to this repo's aspects, local HTTPS, storage, and backups.

Documentation generated by AI.

## Apps and addresses

| App | Web interface | Role | Internal API address |
| --- | --- | --- | --- |
| Prowlarr | <https://prowlarr.glaciem.home> | Searches indexers and syncs them to Sonarr/Radarr | `http://127.0.0.1:9696` |
| Sonarr | <https://sonarr.glaciem.home> | TV discovery, downloads, and library imports | `http://127.0.0.1:8989` |
| Radarr | <https://radarr.glaciem.home> | Movie discovery, downloads, and library imports | `http://127.0.0.1:7878` |
| Deluge | <https://deluge.glaciem.home> | Torrent downloads and seeding | `http://127.0.0.1:8112` (Web UI/API, not daemon port 58846) |
| Bazarr | <https://bazarr.glaciem.home> | Downloads subtitles for Sonarr/Radarr libraries | `http://127.0.0.1:6767` |
| Jellyfin | <https://jellyfin.glaciem.home> | Browses and streams your media | `http://127.0.0.1:8096` |
| Seerr | <https://seerr.glaciem.home> | Discovery and requests, sent to Sonarr/Radarr | `http://127.0.0.1:5055` |

Browser access uses Caddy's internal CA, as with the other homelab apps. Native service ports are not opened in the firewall. Sonarr, Radarr, and Prowlarr bind to loopback; the other apps may listen on all interfaces but remain behind the host firewall. Do not open those ports or expose first-run setup publicly.

## What Nix configures

- Enables the services on Glaciem with HTTPS and Homepage entries.
- Uses the shared `share` user/group for Deluge, Sonarr, Radarr, Bazarr, and Jellyfin so they can access the same files. Prowlarr and Seerr retain isolated dynamic users.
- Creates the library/download directories and adds mount dependencies to media-consuming services.
- Keeps app state under `/var/lib`, which is already persistent on Glaciem and included in its snapshot backups. Adds the six new services to backup quiescing.
- Leaves application accounts, API keys, indexers, quality profiles, and inter-app connections for the initial web setup. No credentials are stored in the Nix store. No SSO, VPN, Usenet, or automatic download sources are added.

Deploy using your usual workflow, for example `just deploy glaciem`. Make sure the new module is tracked by Git first: ordinary Git-backed Nix flakes ignore untracked files. This configuration alone does not begin acquiring media.

## Storage

| Purpose | Default path |
| --- | --- |
| Torrent downloads | `/merged/Downloads/torrents` |
| Movies (Radarr and Jellyfin) | `/merged/Media/Movies` |
| TV (Sonarr and Jellyfin) | `/merged/Media/TV` |

These paths can be changed with `homelab.services.deluge.downloadsDir`, `radarr.libraryDir`, and `sonarr.libraryDir`. Keep downloads outside the library roots. All apps see the same native paths, so remote path mappings are unnecessary.

Downloads and libraries use the same mergerfs view. Sonarr/Radarr can try hardlinks to avoid duplicating files while Deluge seeds, but links require the source and destination to land on the same underlying filesystem. Mergerfs spans the SSD and HDD tiers, so the common `/merged` prefix alone does **not** guarantee hardlinks or atomic moves. Verify imports; cross-filesystem imports may copy and use extra space. Do not relocate or delete existing torrent data blindly.

## First-run setup

### 1. Deluge

1. Log in (a fresh Web UI defaults to password `deluge`) and change the password under **Preferences → Interface**.
2. Connect the Web UI to the local daemon in its Connection Manager. Sonarr/Radarr talk to the Web UI, which must have a working daemon connection.
3. Set **Preferences → Downloads → Download to** to `/merged/Downloads/torrents`. For a simple initial setup, leave **Move completed to** disabled. Existing download settings and existing torrent locations are deliberately not overwritten by Nix.
4. Enable Deluge's **Label** plugin; Sonarr/Radarr use labels to distinguish their downloads.
5. Configure seeding limits to suit your sources. Avoid automatic data removal until successful imports and seeding behavior have been tested.

The current Deluge service uses the normal host network, not VPN isolation.

### 2. Sonarr and Radarr

1. Complete the authentication setup in each app. Keep authentication enabled; there is no external auth gateway. In 1Password, choose **Only fill on this exact host** for each login.
2. Add the TV root `/merged/Media/TV` in Sonarr and movie root `/merged/Media/Movies` in Radarr under **Settings → Media Management**. Enable renaming and **Use Hardlinks instead of Copy** if desired, subject to the storage caveat above.
3. Pick quality profiles and sensible size limits before monitoring anything. Automatic upgrades can consume considerable storage and bandwidth.
4. Under **Settings → Download Clients**, add **Deluge** to each:
   - Host: `127.0.0.1`; port: `8112`; SSL: off; URL base: blank.
   - Password: the Deluge **Web UI** password, not a daemon-auth credential.
   - Category: `tv` in Sonarr, `movies` in Radarr (Deluge labels).
   - Test and save; keep completed download handling enabled.
5. Find each app's API key under **Settings → General** for the connections below. Treat API keys as passwords; do not commit them.

### 3. Prowlarr

1. Set up its authentication and add indexers you are authorized to use. Some require accounts or API keys; Prowlarr does not provide subscriptions.
2. Under **Settings → Apps**, add Sonarr and Radarr using their internal addresses from the table and respective API keys.
3. Use `http://127.0.0.1:9696` as the Prowlarr server address those apps connect back to.
4. Select **Full Sync** if Prowlarr should manage the indexer definitions, then test, save, and sync.

Download clients belong in Sonarr/Radarr for the normal automated workflow. Adding one to Prowlarr is optional for manual grabs from Prowlarr itself.

### 4. Jellyfin

1. Complete its wizard, create an administrator, and add a **Movies** library at `/merged/Media/Movies` and a **Shows** library at `/merged/Media/TV`.
2. Under its networking settings, configure `127.0.0.1` as a known/trusted reverse proxy. Keep the default internal HTTP port for Caddy.
3. Set library languages and enable real-time monitoring or scheduled scans. Seerr's library sync does not replace Jellyfin scanning newly imported files.
4. Create non-admin accounts for everyday playback if wanted. Seerr can use Jellyfin accounts, avoiding an extra end-user password.

Hardware transcoding is not enabled automatically: select and test an appropriate GPU/driver configuration separately. Direct play does not need hardware transcoding. Avoid enabling Jellyfin media deletion or writing metadata into media folders unless you intend it; it runs as the shared media user.

### 5. Bazarr

1. Enable its authentication under **Settings → General → Security**; do not leave the UI unprotected.
2. Connect Sonarr (`127.0.0.1:8989`) and Radarr (`127.0.0.1:7878`) with their API keys; use HTTP internally.
3. Configure subtitle providers, preferred languages, and a language profile. Assign that profile to the shows/movies you want managed.
4. Use the existing library paths without path mappings. Bazarr writes subtitle files next to the media, where Jellyfin can discover them.

### 6. Seerr

1. Select Jellyfin in the setup wizard and connect to `http://127.0.0.1:8096`, signing in with a Jellyfin administrator for the initial integration.
2. Set the externally reachable Jellyfin URL to `https://jellyfin.glaciem.home` wherever Seerr asks for the public/external address; browser links must not point to loopback.
3. Sync the movie/TV libraries and connect Radarr and Sonarr using their internal addresses and API keys.
4. Mark each as its default server, select the appropriate library root and quality profile, and enable the server. Enable automatic searching on requests if desired.
5. Set request permissions, approval requirements, and user quotas before allowing additional users. Jellyfin users can sign into Seerr; a separate local Seerr account is not required for each person.

## Smoke test

Use a release you are authorized to download. Add/request one title, verify indexer search, then follow it through Sonarr/Radarr's queue, Deluge completion, library import, and Jellyfin playback. Confirm Bazarr retrieves the expected subtitles and Seerr eventually marks the title available.

On Glaciem, check service health with:

```sh
systemctl status sonarr radarr prowlarr bazarr jellyfin seerr deluged delugeweb
journalctl -u sonarr -u radarr -u prowlarr -u bazarr -u jellyfin -u seerr -b
```

Check hardlinks with `stat` on the download and library files: a successful hardlink shares the device/inode and has a link count of at least two. Check the applications' import logs if the filesystem view makes this ambiguous.
